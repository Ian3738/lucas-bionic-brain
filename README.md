# Lucas · 仿生大腦

一顆會長大的仿生大腦。拖滑桿讓它從新生兒走到專家，喊一聲「Hi, Lucas」跟它說話 ——
**它在哪一格，就用哪一格的腦回答你。**

🌐 <https://ian3738.github.io/lucas-bionic-brain/>

---

## 這頁想給學生看什麼

同一個問題，問八次。

| 階段 | 它會怎麼答「天空為什麼是藍的？」 |
|---|---|
| 新生兒 | 咿咿呀呀。還沒有語言。 |
| 幼兒 | 「嗯，被藍色筆畫畫了。」 |
| 青春期 | 「就光的散射啊不然勒！我跟你說……我也懶得背那些很煩的物理名詞。」 |
| 專家 | 講到瑞利散射，交代這個解釋的適用邊界，然後反問你想問的是晴天還是日落。 |

差別不只在深淺，在**它拿什麼來答**：早期用想像補，中期用情緒衝，晚期才回頭查自己。

畫面同步演這件事。問它問題的時候，訊號實際走哪一條鏈是**綁在階段上的**，不是隨機裝飾：

- 新生兒與幼兒 → `deadEnd`，線接到鏈上沒有的角色
- 學齡前到青春期 → `returnLimit`，在兩個腦區之間原地繞圈（乒乓球退化）
- 青年之後 → `done`，走得完整合輸出那一圈

腦區點亮的順序照真實的發育順序：杏仁核與海馬迴早熟、預設模式網絡在青春期成形、
前額葉最晚、後設監控的查核守衛最後。灰掉的是「還沒有人教它這一塊」。

> ⚠ **「大腦發展到 25 歲」方向對、數字是約定。**
> 前額葉與它的白質連結確實成熟得最晚、延續到二十多歲，但發育是連續的、個體差異很大。
> 25 是好記的標記，不是一條線。跟學生講的時候把這句一起講，否則會變成「生日一過就換了顆腦」。

> ⚠ **最後一格「專家」不是年齡，是專精。** 一顆被教得紮實的腦不會因此變老。
> 混在同一條滑桿上是為了教學方便，這件事要對學生講明。

## 怎麼用

1. 開網頁，貼上你的 [Gemini API 金鑰](https://aistudio.google.com/apikey)（免費申請）。
2. 按「開麥克風，等我喊 Lucas」，允許麥克風。
3. 喊「**Hi, Lucas**」→ 它醒來 → 直接問問題。醒來後 30 秒內不用再喊名字，
   而且**這 30 秒是從它講完開始算的**，它想的時候、唸的時候都不倒數。
4. 拖滑桿換階段，按「**換現在的階段，同一題再答一次**」。

整頁最重要的就是第 4 步：問一次、拖滑桿、再按一次，同一題的兩個答案並排在同一串裡。

### 用講的也能操控

| 說 | 它做 |
|---|---|
| 「Lucas，長大」／「變小」 | 換上一格／下一格 |
| 「Lucas，變成青春期」 | 直接跳到那一格 |
| 「停」「安靜」「閉嘴」 | 閉嘴 —— 只在它**還在想**的時候有用 |
| 「Lucas，重播」 | 訊號再走一次 |

> ⚠ **它開口之後就聽不到你了。** 發聲期間辨識器是停著的（不然它會聽見自己講的話），
> 所以「用講的喊停」在那段時間物理上不可能成功。要打斷請按畫面右下角的 **■ 停**，或按 Esc。

喚醒詞的比對含大量誤聽變體（路卡斯、盧卡斯、魯卡斯、露卡斯⋯⋯），
因為辨識引擎設 zh-TW，Lucas 十次有八次會被寫成中文。寧可寬，也不要學生喊三次叫不醒。

## 技術

沒有後端、沒有建置流程、沒有相依套件。一個 `index.html`，開了就跑。

| 用途 | 模型 |
|---|---|
| 對話 | `gemini-3.8-flash`，串流端點，`thinkingBudget: 0` |
| 發聲 | `gemini-3.1-flash-tts-preview`，**串流端點**，失敗退 `gemini-2.5-flash-preview-tts`，再失敗退瀏覽器內建語音 |
| 聽 | 瀏覽器的 Web Speech API（zh-TW，持續辨識） |
| 播放 | Web Audio API 排程佇列（不是 `<audio>`，碎塊播不了） |
| 畫面 | 原生 Canvas 2D，約 3,100 顆粒子 |

### ⚠ 最大的一個坑：TTS 一定要用串流端點

同一支模型、同一個嗓音、同一段風格提示，`:generateContent` 和 `:streamGenerateContent?alt=sse`
合成出來的音訊**完全一樣**，差別只在什麼時候拿得到第一個 byte：

| 端點 | 第一個音 |
|---|---|
| `:generateContent` | 一則 163 字的回答要等 **20.8 秒**，而且跟音訊長度成正比（`1.67 + 0.518 × 音訊秒數`） |
| `:streamGenerateContent?alt=sse` | **1.0 秒**，跟文字長度幾乎無關 |

改版前整條鏈是 23.08 秒，TTS 一個人佔掉九成。改完之後端到端實測 2.5 秒。
串流回來的每一塊是 1920 bytes（0.04 秒 PCM），`<audio>` 播不了這種碎塊，
要用 Web Audio 自己排：每塊轉 `AudioBuffer`，接在 `playHead` 上依序 `start()`。

有了串流就**不要再切塊**。切塊是為了讓第一個音早點出來，串流本來就第一塊出聲；
切了反而讓每塊語調各自從頭開始，接縫聽得出來。

其他踩過的坑：

- **TTS 回的是裸 PCM**（`audio/L16`、24 kHz、單聲道），瀏覽器不吃，要自己補 44 bytes 的 WAV 表頭。
- **語速用講法指示控制，不要用 `playbackRate`。** 事後加速會把共振峰一起壓縮，聽起來就是快轉。
  實測同一句話：不給指示 7.84 秒，「語速比平常快很多，中間幾乎不停頓」5.32 秒，「很慢很疲倦」12.96 秒。
- **用 `thinkingBudget: 0`，不要用 `thinkingLevel: "low"`。** 實測 21 次 low 有 2 次仍然吐出思考 token；
  而「完全不帶 `thinkingConfig`」那條退路更糟 —— 5 次全部 `MAX_TOKENS`，其中一次把英文思考內容
  當答案吐出來，那會被原樣唸出聲。
- **打斷的關鍵字要整句比對。** 把「停」直接放進 `|` 串裡，「為什麼心臟會停」也會被當成打斷指令。
- **被 `reader.cancel()` 打斷的串流是從「正常結束」那條路出去的，不是 catch。**
  `cancel()` 會讓等待中的 `read()` 以 `done: true` 回來，所以讀完迴圈後一定要再檢查一次世代，
  否則只收到一半的音訊會被寫進快取，那句話從此整堂課都只唸半截。
- **串流中途會送 error frame，而 HTTP 狀態早就是 200 了。** 不看 `j.error` 和 `finishReason`
  的話，半段答案會被當成完整答案唸出來、還寫進對話歷史。
- **發聲用的人格要在提問當下就鎖住**，不能在 `say()` 裡才讀滑桿。模型在想的時候老師若拖了滑桿，
  專家的答案會用嬰兒的嗓音唸出來 —— 而拖滑桿正是上課時最常做的動作。
- **收尾一定要放 `finally`，而且要保留世代守衛。** 少了 `finally`，任何例外都會讓 `recPaused`
  卡在 true，麥克風永久聾掉而畫面上的燈還亮著；少了守衛，被打斷的舊世代會在新世代講話時
  把麥克風打開，它就聽見自己了。
- **喚醒視窗的倒數不能在它講話的時候跑。** 專家階段一則回答就是 35 秒的音訊，
  倒數要是從喚醒當下起算，等它唸完視窗早就過期了，使用者接著追問會被靜默丟掉 ——
  症狀是「回答完一次之後它再也聽不到我講話」，但其實麥克風好好的，只是它不覺得你在跟它講話。
  倒數只在閒著等使用者講話時跑（`armAwake()`），忙碌時不掛計時器。
- **`continuous = true` 讓「講完了」的判定沒有上限。** Chromium 的 `speech_recognizer_impl.cc` 裡，
  非連續模式的靜默門檻是 0.5～1 秒，連續模式放寬到 15 秒，還會忽略伺服器的 `END_OF_UTTERANCE`。
  喚醒詞需要連續模式，拿不掉。曾經加過「即時辨識停 1.1 秒就當講完」的搶快邏輯，但它會在中文
  句中停頓時送出半句、而且同一句的 `isFinal` 會把指令再執行一次（說一次「長大」跳兩格），
  省下多少時間又從來沒量到過，所以拿掉了。沒量到的收益不值得換三個會當眾出錯的失敗模式。
- **注音選字的 Enter 要擋掉**（`e.isComposing`），否則用中文輸入法的人每選一次字就送出半截句子。
- **退到瀏覽器語音時要等它講完再開麥克風**，否則它會聽見自己，然後自問自答。
- **語音辨識只在 Chrome 和 Edge 穩定**，Safari 和 Firefox 支援很差。這是瀏覽器的限制。
- `gemini-3.5-transcribe` 的結果放在 `audioTranscription.text`，不是 `text`。
- 沒有 `gemini-3.6` / `3.8` 的 TTS 版本。會發聲的最新一支就是 3.1。

新生兒那一格不呼叫模型，在本機亂數生成牙牙學語 —— 即時、不耗額度，
而且每次都不一樣，正好就是「這裡還沒有語言」。
